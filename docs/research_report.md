# 温州话语音到普通话文本转换 Agent 技术调研报告

## 1. 项目背景

温州话属于高度复杂的汉语方言/吴语系统，普通话使用者通常难以直接理解。对真实应用而言，最有价值的产品不是“温州话文字翻译”，而是：

> 温州话语音输入 → 普通话文本输出 → 普通话语音播报

该路线可以服务于医院、政务窗口、跨地域家庭沟通、商务接待、文旅服务和老年人数字化辅助。

## 2. 温州话为什么难

### 2.1 低资源

公开标注数据稀缺。LoResMT 2025 的论文指出，温州话缺乏公开可用数据集，并构建了温州话语音与普通话文本的平行数据作为基准。

### 2.2 无正式书写系统

温州话很难稳定写成标准文本。因此推荐直接做 speech-to-Mandarin text conversion，而不是先转温州话文本再翻译。

### 2.3 语音差异大

温州话与普通话在声母、韵母、声调和连读方面都有显著差异，普通话 ASR 直接识别容易产生高 CER。

### 2.4 词汇和语序差异

仅靠 ASR 不足以解决问题。工程上应增加普通话语义纠错模块，将 ASR 原始文本改写为自然普通话。

## 3. 相关研究

### 3.1 Wenzhou Dialect Speech to Mandarin Text Conversion, LoResMT 2025

该论文建立了温州话语音到普通话文本转换任务，并构建平行数据集和基线模型。其意义是把温州话从“无数据、难评估”的状态推进到“可训练、可比较”的状态。

建议在后续 README 和论文中引用该工作。

### 3.2 TeleSpeech-ASR

TeleSpeech-ASR 是面向中文多方言语音识别的开源模型方向，官方说明包含温州话等多个方言。该模型适合作为本项目的强基线后端。

### 3.3 FireRedASR / FireRedASR2S

FireRedASR 是工业级开源 ASR 系列，支持普通话、中文方言和英文。FireRedASR2S 集成 ASR、VAD、LID 和标点模块，适合工程化部署和真实产品 Demo。

### 3.4 FunASR / Paraformer

FunASR 是工业级语音识别工具链，适合中文 ASR、标点、VAD、说话人相关任务。Paraformer 对中文普通话和部分方言场景具备高效率优势，可作为部署友好型后端。

### 3.5 faster-whisper

faster-whisper 适合快速构建 baseline，部署简单，但对温州话这类低资源方言的效果可能有限。建议作为 fallback，而不是最终核心模型。

---

## 4. 推荐技术路线

### MVP 推荐架构

```text
Audio
  → preprocess 16k mono wav
  → ASR
  → Mandarin normalizer
  → TTS
  → correction data collection
```

### 为什么不直接训练大模型

直接微调 TeleSpeech 或 Wav2Vec2-XLS-R 需要 GPU、训练数据、调参和评估闭环。对于当前阶段，更高性价比是先完成可运行工程，再通过人工纠错数据逐步形成专属数据壁垒。

---

## 5. 模型优先级

| 优先级 | 模型/工具 | 用途 |
|---|---|---|
| 1 | FireRedASR2S | 工程化 ASR + VAD + LID + 标点 |
| 2 | TeleSpeech-ASR | 多方言强基线，重点关注温州话 |
| 3 | FunASR / Paraformer | 中文 ASR 和部署效率 |
| 4 | faster-whisper | 快速 baseline |
| 5 | Wav2Vec2-XLS-R | 后续低资源微调 |

---

## 6. 数据集设计

### 6.1 最小可用数据

建议先采集 5–10 小时高质量温州话音频：

- 16 kHz mono wav
- 每条 3–15 秒
- 每条配普通话标准文本
- 保留原始音频和清洗后音频
- 标注说话人、性别、年龄、场景、噪声等级

### 6.2 推荐扩展数据

要做出明显效果，建议累计 20–50 小时。要投稿或产品化，建议向 100 小时以上扩展。

---

## 7. 评估方案

1. CER：中文字符错误率，核心指标
2. WER：分词后词错误率
3. BLEU / ChrF：用于普通话重写质量
4. 人工可理解度：1–5 分
5. 任务成功率：用户是否能理解最终普通话
6. 延迟：上传到返回结果的时间
7. 鲁棒性：噪声、多人、口音、长句

---

## 8. 风险分析

| 风险 | 影响 | 解决方案 |
|---|---|---|
| 温州话数据少 | 识别差 | 建立人工纠错闭环 |
| 普通话 ASR 误识别 | 输出不稳定 | 使用多方言 ASR 后端 |
| 词序和词汇差异 | 普通话不自然 | 增加 LLM normalizer |
| 模型过大 | 部署困难 | 先 mock/faster-whisper，再接轻量模型 |
| 隐私风险 | 声音数据敏感 | 本地存储、授权采集、脱敏处理 |

---

## 10. 结论

本项目最合理路线是：先完成工程 MVP，再用人工纠错数据建立壁垒，最后微调多方言 ASR 或 speech-to-Mandarin 模型。当前版本重点是可运行、可展示、可扩展。
